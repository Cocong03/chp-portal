Sales Orders (mcrmSalesOrders), adding to the status request

1. status should be filterable ($filter=status eq 'Released'), not just returned. Then the status filter works and the dashboard can count orders with $count, so a separate "SO counts by status" API (S2-10) isn't needed.
2. documentType, so the portal can stop filtering on the SOR prefix. The API also returns blanket orders (BSO), credit memos (SCM) and invoices (SIN).
3. Archived orders: the shipped or invoiced orders. In the same API or a second one, but with the same fields. Without them the portal can't show "Completely Shipped" or "Invoiced".
4. Ship method: how to tell Pick up from Delivery. shipmentMethodCode is empty on every order, so tell us which field holds it and its values.
5. Trip ID and the date it was assigned. tripEntryNo is empty. Is it the same field as BC's "Current Trip Entry No." column?
6. Expected delivery date. requestDeliveryDate is empty. Which field does BC use for it?
7. Blanket SO # on an order created from a blanket order.
8. Lines (chpSalesOrderLines): does unitPrice include VAT?
